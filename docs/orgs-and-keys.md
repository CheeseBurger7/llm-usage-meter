# Orgs and API keys (storage)

An org is one paying customer. Every other table will be scoped to an org, and
an API key is how a request proves which org it belongs to. This page covers
the tables and queries only; key generation, verification and the HTTP
middleware are separate tasks in [TASKS.md](TASKS.md).

## Tables

Migration: `internal/storage/migrations/00003_create_orgs_api_keys.sql`.

`orgs`

| Column | Type | Notes |
|---|---|---|
| `id` | `UUID` | Primary key, `gen_random_uuid()` |
| `name` | `TEXT` | Not empty. Not unique: two customers may share a display name |
| `created_at` | `TIMESTAMPTZ` | Defaults to `now()` |

`api_keys`

| Column | Type | Notes |
|---|---|---|
| `id` | `UUID` | Primary key, `gen_random_uuid()` |
| `org_id` | `UUID` | References `orgs(id)`. An org with keys cannot be deleted |
| `key_hash` | `BYTEA` | SHA-256 of the plaintext key, exactly 32 bytes, unique |
| `prefix` | `TEXT` | Short non-secret part of the key, shown to humans. Indexed, not unique |
| `scope` | `TEXT` | `ingest` or `read` |
| `created_at` | `TIMESTAMPTZ` | Defaults to `now()` |
| `revoked_at` | `TIMESTAMPTZ` | `NULL` while the key is active |

The plaintext key is never stored. The database rejects a `key_hash` that is
not 32 bytes, so a caller cannot store a plaintext key by mistake.

## Queries

In `internal/storage/queries/orgs.sql` and `api_keys.sql`:

| Query | Use |
|---|---|
| `CreateOrg`, `GetOrg` | Create and read an org |
| `CreateAPIKey` | Store a new key's hash, prefix and scope |
| `GetAPIKeyByHash` | Lookup on every authenticated request. Returns revoked keys too; the caller checks `revoked_at` |
| `ListAPIKeysByOrg` | Keys of one org, oldest first, without `key_hash` |
| `RevokeAPIKeysByPrefix` | Sets `revoked_at` on active keys with that prefix and returns the count. Safe to re-run |

## Design decisions

- **UUID ids, generated by Postgres.** Org and key ids will appear in URLs,
  logs and exports. Random ids do not reveal how many customers exist and
  cannot be guessed by counting. The cost is 16 bytes per reference instead
  of 8. See Q11 in [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md).
- **Keys are revoked, not deleted.** `revoked_at` keeps the row, so a rejected
  request can be told apart from an unknown key and there is a record of when
  access ended.
- **`prefix` is not unique.** Uniqueness would make key creation fail on a
  random collision. Revoking by prefix therefore revokes every active key
  with that prefix and reports the count, so the caller can see when it was
  more than one.
- **`scope` is `TEXT` with a `CHECK`, not an enum type.** Adding a scope later
  is a one-line constraint change.
